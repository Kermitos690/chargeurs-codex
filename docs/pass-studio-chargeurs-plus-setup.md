# Chargeurs+ — Pass Studio setup contract

Pass Studio is only the Wallet presentation/distribution provider. Chargeurs.ch remains canonical for membership status, pricing and ChargePoints.

## Provider account

Create one active Pass Studio pass named exactly `Chargeurs+` (or set `PASS_STUDIO_PASS_ID` / `PASS_STUDIO_PASS_NAME` server-side).

The public Pass Studio REST API currently lists, issues and updates passes; creation/design is performed in the Pass Studio studio UI. There is no documented REST endpoint for creating the visual template itself.

## Required editable per-holder field keys

Create these editable fields on the Chargeurs+ template:

| key | source of truth | example presentation |
| --- | --- | --- |
| `membership_status` | `customer_memberships.status` | `Pass actif` |
| `membership_name` | `customer_membership_plans.name` | `Chargeurs+` |
| `member_rate` | active membership plan | `CHF 0.75 / h` |
| `daily_cap` | active membership plan | `CHF 9.00 / jour` |
| `chargepoints` | `customer_chargepoints_balances.balance` | `155` |
| `valid_until` | membership period end | `30.09.2027` |

Do not mark those keys as template-owned. The backend reads `/passes` metadata and only sends fields that Pass Studio reports as editable for the individual holder.

## Recommended front-face hierarchy

- Chargeurs+ logo / battery mark
- `membership_status`
- `chargepoints` as the strongest personal value
- compact `member_rate`
- barcode/QR generated by Pass Studio

Keep `daily_cap`, `membership_name` and `valid_until` secondary to avoid overloading Apple/Google Wallet.

## Required server secrets

- `PASS_STUDIO_API_KEY` — secret API key; server only
- optional `PASS_STUDIO_PASS_ID` — preferred explicit template binding
- optional `PASS_STUDIO_PASS_NAME` — defaults to `Chargeurs+`

Never expose these through Vite variables, browser storage, HTML, logs or Git.

## Runtime flow

1. Authenticated customer opens `/compte/pass`.
2. The UI calls the already-deployed `account-privacy` Edge Function with `action: "wallet_pass"`.
3. Edge Function verifies the Supabase account and active Chargeurs+ membership.
4. Edge Function resolves the active Pass Studio template.
5. First issue uses `POST /passes/{passId}/issue` with `sendEmail:false`.
6. Dedupe is provider-side by customer email.
7. The instance is immediately synchronized with `PATCH /instances/fields` because Pass Studio documents that fields are not reapplied on a dedupe hit.
8. Chargeurs persists only provider IDs, barcode and the hosted `addToWalletUrl`; never the provider API key.
9. Browser receives only the safe hosted Add-to-Wallet URL and navigates to it.

`account-privacy` is intentionally reused because the current Supabase project has reached its Edge Function count limit. No function is deleted and no paid plan upgrade is required for this integration.

## Failure behavior

Provider outage/configuration failure must not change membership, pricing, rentals, ejection or return state. The Wallet card reports a temporary issuance error and the customer's Chargeurs+ membership remains unchanged.
